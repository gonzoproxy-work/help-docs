# 👥 Cубаккаунты

**Sub Users** — это дополнительные аккаунты внутри вашего основного аккаунта GonzoProxy. Эта функция позволяет распределять трафик между членами команды, контролировать расход каждого пользователя и ограничивать доступ к общему балансу. Также Sub Users можно использовать для личных целей, создавая отдельные аккаунты для разных задач в рамках одного основного аккаунта.

***

1. **Как создать дополнительный аккаунт**

**Шаг 1.** Перейдите на вкладку **Sub Users** в меню панели управления.

<figure><img src=".gitbook/assets/4 (11).png" alt=""><figcaption></figcaption></figure>



**Шаг 2.** Нажмите кнопку **Добавить пользователя**.

<figure><img src=".gitbook/assets/5 (8).png" alt=""><figcaption></figcaption></figure>



**Шаг 3.** Введите количество GB, которые хотите выделить на этот аккаунт, укажите имя, email, через который можно будет войти в дополнительный аккаунт и нажмите **Save**.&#x20;

{% hint style="info" %}
На указанный email будут отправлены данные для входа в новый суб-аккаунт GonzoProxy. После получения логина и пароля пользователь сможет войти в личный кабинет и использовать суб-аккаунт отдельно в рамках основного аккаунта.
{% endhint %}

<figure><img src=".gitbook/assets/1.jpg" alt=""><figcaption></figcaption></figure>



Система начнёт создание аккаунта автоматически.

***

#### Что означают поля в таблице

<figure><img src=".gitbook/assets/6 (7).png" alt=""><figcaption></figcaption></figure>

| Поле      | Описание                                          |
| --------- | ------------------------------------------------- |
| Username  | Имя дополнительного аккаунта                      |
| Login     | Логин дополнительного аккаунта                    |
| Password  | Пароль от прокси этого аккаунта                   |
| Limit     | Выделенный лимит трафика (GB)                     |
| Used      | Сколько GB уже использовано                       |
| Status    | Текущий статус аккаунта (активен / деактивирован) |
| Actions   | Управление аккаунтом                              |

***



2. #### Управление аккаунтом

В столбце **Actions** напротив каждого sub-аккаунта доступно:  <br>

* Деактивация аккаунта
* Изменение имени дополнительного аккаунта
* Изменение email
* Изменение лимита трафика



<figure><img src=".gitbook/assets/2.jpg" alt=""><figcaption></figcaption></figure>



* **Деактивация** мгновенно останавливает аккаунт и все прокси, которые на нём работают. Это первое действие при увольнении сотрудника — сотрудник теряет доступ немедленно.<br>
* **Изменение имени** дополнительного аккаунта позволяет в любой момент переименовать аккаунт для более удобного управления и идентификации внутри команды.<br>
* **Изменение email** позволяет назначить новый адрес электронной почты для дополнительного аккаунта. После изменения владелец указанного email сможет использовать его для входа в этот аккаунт.<br>
* **Изменение лимита** позволяет в любой момент увеличить или уменьшить объём GB на конкретном аккаунте. Именно через это действие тимлид вручную забирает неиспользованный трафик уволенного сотрудника: нужно обнулить лимит и перераспределить освободившиеся GB на других участников команды.



В поле **Actions** также доступна функция удаления дополнительного аккаунта.

<figure><img src=".gitbook/assets/9 (3).png" alt=""><figcaption></figcaption></figure>

***



3. #### Как создать прокси для дополнительного аккаунта

**Шаг 1.** После создания аккаунта перейдите в **генератор прокси** и выберите нужный sub-аккаунт из выпадающего списка.

<figure><img src=".gitbook/assets/2 (17).png" alt=""><figcaption></figcaption></figure>



**Шаг 2.** Настройте параметры: выберите страну, город или провайдера, укажите режим ротации.

<figure><img src=".gitbook/assets/8 (5).png" alt=""><figcaption></figcaption></figure>



**Шаг 3.** Нажмите Создать прокси — готовые прокси появятся в списке и будут работать в рамках лимита выбранного аккаунта.

***

{% hint style="info" %}
💡 Совет: Sub Users удобны для команд, где несколько сотрудников работают с прокси независимо друг от друга. Каждый аккаунт расходует только свой выделенный лимит — основной баланс защищён.
{% endhint %}
